# АЗБУТ — переработанный сайт с админкой

Полная переработка `azbut.by`: сохранена общая стилистика (тёмно-коричневый + оранжевый `#fcbf5b`, индустриальные фото, логотип с шестернёй и львом), но полностью переписаны вёрстка, SEO, производительность, доступность и добавлена серверная админ-панель.

> Проект сделан как **рабочий прототип на чистом Node.js без внешних зависимостей**: его можно запустить сразу, без `npm install`, базы данных и сборщика.

---

## Быстрый запуск

```bash
cd /home/user/azbut-rebuild
npm start          # либо: node server.js
```

Откройте `http://localhost:3000/` (в Arena — живой preview на порту 3000).

> Режим preview: пока `SITE_ORIGIN` не задан, сервер не блокирует встраивание в iframe (`X-Frame-Options` не выставляется, CSP → `frame-ancestors *`). Для продакшена задайте `SITE_ORIGIN=https://azbut.by` — тогда вернётся строгий `SAMEORIGIN`.

| Раздел | URL |
|---|---|
| Сайт RU | `/` |
| Сайт EN | `/en` |
| Каталог | `/catalog`, `/en/catalog` |
| Карточка товара | `/product/:slug` |
| Услуги | `/services`, `/services/:slug` |
| Админка | `/admin` |
| Логин | `/admin/login` |
| Sitemap / Robots | `/sitemap.xml`, `/robots.txt` |
| Healthcheck | `/health` |

**Демо-доступ:** `admin` / `Azbut2026!`  
После первого входа смените пароль в разделе **Безопасность**.

Переменные окружения:

```bash
PORT=3000 HOST=0.0.0.0 \
SESSION_SECRET='длинный-случайный-секрет' \
ADMIN_PASSWORD='ваш-пароль' \
SITE_ORIGIN='https://azbut.by' \
node server.js
```

Полезные команды:

```bash
npm run reset          # вернуть данные к seed/ (971 реальная позиция)
npm run import:tilda   # переимпорт каталога azbut.by из Tilda Store API (нужен Pillow для фото)
npm run build:static   # пересобрать статику docs/ для GitHub Pages
npm run push:pages     # запушить main с новым PAT из GH_TOKEN или /tmp/gh_token
npm run check          # smoke-тест всех маршрутов, SEO, логина, CSRF и формы заявки
```

## GitHub Pages

| | |
|---|---|
| Репозиторий | `https://github.com/mokoaibot/azbut-ai-site` |
| Ветка / папка | `main` → `/docs` |
| Опубликованный сайт | `https://mokoaibot.github.io/azbut-ai-site/` |

Pages раздаёт **статический снимок** публичной части, сгенерированный из тех же данных и шаблонов. Каталог на Pages содержит **все товары сразу**: поиск, фильтры, сортировка и пагинация выполняются в браузере (`public/assets/js/site.js`), поэтому query-страницы вида `?page=2` больше не нужны. Готовый `docs/` собирается локально; после пуша в `main` включите Pages в **Settings → Pages → Build and deployment → Deploy from a branch → Branch `main`, folder `/docs` → Save**. Публикация обычно занимает 1–2 минуты.

```bash
npm run import:tilda   # 971 позиция, 50 брендов, 338 локальных WebP (при первом импорте)
npm run build:static   # пересобрать docs/ (1970 страниц RU+EN, ассеты, sitemap, robots, 404)
git add docs && git commit -m "Update static build" && git push
```

Скрипт `scripts/build-static.js` поднимает временный SSR-сервер с `SITE_ORIGIN=https://mokoaibot.github.io`, обходит все страницы и переписывает пути под базу `/azbut-ai-site`: ассеты, внутренние ссылки, `canonical`, `hreflang`, OG и JSON-LD. Добавляются `.nojekyll`, `404.html`, `sitemap.xml`, `robots.txt` и заглушка `/admin/`.

Автодеплой через GitHub Actions — шаблон `scripts/pages-workflow.yml.example`. Чтобы запушить его как `.github/workflows/pages.yml`, токену нужен `workflow` scope, а для включения Pages через API — `Pages: write`. Переданный ранее PAT удалён после пуша. Для нового пуша: `GH_TOKEN=... npm run push:pages` либо положите ключ в `/tmp/gh_token` (`chmod 600`) и запустите ту же команду — скрипт сам клонирует репозиторий, скопирует проект, закоммитит, запушит и удалит временный токен. Для автоматического включения Pages через API нужен токен с `Pages: write`; ручной source из ветки уже работает.

**Важное ограничение:** GitHub Pages не умеет запускать Node.js. Поэтому на Pages:

- работают витрина, каталог, карточки товаров, услуги, RU/EN, SEO-разметка и адаптив;
- **не работают** админка, REST API, запись в JSON, загрузка картинок и отправка заявок — в формах показывается аккуратное пояснение;
- полный сайт с админкой нужно размещать на VPS / Render / Railway / Fly.io и т.п. (`npm start`).

Поиск и фильтры каталога на Pages при этом работают — в отличие от серверных функций выше.

Токены и `.env` в репозиторий не коммитятся: `.gitignore` исключает `data/audit.log`, бэкапы и загрузки. Переданный в чате PAT рекомендуется отозвать и выпустить заново с минимальными правами.

## Реальный каталог azbut.by

`scripts/import-tilda.py` тянет публичный Tilda Store API (`storepartuid=686800396042`), который отдаёт **971 позицию** двумя слайсами по 500/471. Результат:

| | |
|---|---|
| Товаров | 971 (все `published`) |
| Брендов | 50 (включая 8 исходных с описаниями) |
| Разделов | 6: Быстрая доставка 429, John Deere 263, CLAAS 252, CNH Industrial 20, DEUTZ AG 6, Разное 1 |
| Фото | 338 уникальных изображений → локальные WebP 700 px / q72, 13.5 МБ; у 220 товаров есть фото, у 751 — `placeholder.svg` |
| Цены | у всех `null`: в источнике реальных цен нет, поэтому schema.org `Offer` не выпускается |

Скрипт сам скачивает фото (нужен `Pillow`), приводит `gallery`/`editions`/`partuids` из строк Tilda к нормальным структурам, вычищает HTML из описаний, берёт slug из `/tproduct/...` и пишет одинаковые `data/products.json` + `seed/products.json`. Сырой ответ сохранён в `/home/user/azbut_audit/tilda_products_raw.json`; флаги `--offline`, `--skip-images`, `--limit N` удобны для повторных прогонов.

**Оговорки о качестве исходных данных:** названия и описания только на русском, поэтому EN-страницы оставляют оригинальную формулировку поставщика, а не выдумывают перевод; часть значений в поле «Бренд» — это нарицательные слова (`МЕТИЗЫ`, `ЦЕПИ`, `ПОДШИПНИК`); наличия и цен в API нет, поэтому все карточки честно показывают «Цена по запросу» / «Под заказ».

Для масштаба добавлены: кэш `store.read()` по `mtime`, полный список категорий в фильтре (`allProducts`), компактная пагинация «← 1 2 3 … 122 →» на сервере и в статике, динамический slug в `scripts/check.js`.

## Архитектура

```
azbut-rebuild/
├── server.js                 # роутер, SSR, REST API админки, sitemap/robots
├── package.json              # zero-dependency, Node >= 20
├── lib/
│   ├── config.js             # пути, порт, секреты, лимиты
│   ├── store.js              # JSON-хранилище: atomic write, backup, audit.log
│   ├── auth.js               # scrypt, подписанные сессии, CSRF, rate-limit логина
│   ├── http.js               # заголовки безопасности, gzip, статика, body-парсер
│   ├── validation.js         # slugify, cleanText/Url, валидация лидов и товаров
│   ├── render.js             # layout, шапка/футер, формы, карточки, JSON-LD, админ-shell
│   └── views.js              # публичные страницы
├── public/assets/
│   ├── css/site.css          # адаптивная вёрстка 320–1440+
│   ├── css/admin.css         # админка
│   ├── js/site.js            # бургер, формы, галерея
│   ├── js/admin.js           # SPA-админка на ванильном JS
│   └── img/                  # локальные WebP/SVG (изображения с исходного сайта)
├── data/                     # рабочие JSON + audit.log + backups/
├── seed/                     # эталонные данные для npm run reset
└── scripts/
    ├── reset.js
    └── check.js
```

### Принципы

- **SSR first:** весь контент есть в HTML до JS; поисковик не зависит от XHR.
- **Один источник данных:** `data/*.json`, редактируется через админку.
- **Atomic writes:** запись во временный файл + `rename`, перед каждой записью — backup (до 12 копий на файл).
- **Разделение ответственности:** роутер / store / auth / http / render / views / validation.
- **Без внешних CDN:** CSS, JS, шрифты (системные) и изображения — локальные.
- **Двуязычие:** `ru` и `en` поля в данных, префикс `/en`, `hreflang`, переключатель языка.

## Админ-панель

Разделы:

1. **Дашборд** — счётчики товаров/заявок/услуг/медиа, последние лиды и журнал.
2. **Товары** — создание/редактирование/удаление, slug, артикул, бренд, категория, RU/EN тексты, цена, наличие, SEO-поля, загрузка изображения, публикация.
3. **Услуги** — CRUD, иконка, порядок, изображение, RU/EN, SEO.
4. **Бренды** — CRUD, RU/EN описание.
5. **Страницы и SEO** — правка title/description/H1/hero/текстов для `home`, `about`, `contacts`, `vacancies`, `terms`.
6. **Заявки** — статусы `Новая / В работе / Закрыта / Спам`, удаление.
7. **Настройки** — контакты, мессенджеры, адрес, УНП, режим работы, футер, ID Метрики и GA4.
8. **Медиа** — загрузка PNG/JPEG/WebP до 3 МБ, копирование пути, удаление.
9. **Безопасность** — смена пароля, информация о сессии.
10. **Журнал** — все изменения с датой, пользователем, действием и IP.

### Безопасность админки

- Пароль: `scrypt` + случайная соль, в `users.json` хранится только хеш.
- Сессия: случайный токен, HMAC-подпись cookie, `HttpOnly`, `SameSite=Lax`, TTL 7 дней.
- CSRF: отдельный токен в сессии; все POST/PUT/PATCH/DELETE требуют `X-CSRF-Token`.
- Публичные формы: stateless HMAC-токен, привязанный к IP и временному окну + honeypot.
- Логин: до 5 попыток, затем блокировка на 10 минут; неудачные попытки пишутся в аудит.
- Загрузки: проверка MIME/data-URL, магических байт, размера, случайное имя файла, запрет path traversal.
- Security headers: HSTS, CSP, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. `X-Frame-Options: SAMEORIGIN` и `frame-ancestors 'self'` включаются только при заданном `SITE_ORIGIN`; в dev/preview фрейминг разрешён, чтобы live-preview открывался в iframe.

## SEO и доступность

- Уникальные `title` / `meta description` / `canonical` / OG / Twitter на каждой странице.
- `hreflang="ru"`, `hreflang="en"`, `x-default`.
- JSON-LD: `Organization`, `LocalBusiness`, `WebSite`, `BreadcrumbList`, `ItemList`, `Product`, `Offer` (только при реальной цене).
- Один `<h1>`, семантические `header/nav/main/footer/article`, breadcrumbs, skip-link.
- `alt`, `width`/`height`, `loading="lazy"`, `decoding="async"`, `srcset` для hero.
- Tap-target ≥44 px, visible focus, AA-контраст, `prefers-reduced-motion`.
- Формы с `<label>`, `autocomplete`, `aria-required`, `role="status"`, согласием на обработку данных.
- `robots.txt` закрывает `/admin/`, `/api/`, `/data/`; sitemap генерируется из данных.

## Ограничения прототипа и что делать для продакшена

1. **JSON вместо БД.** Для боевого сайта замените `lib/store.js` на PostgreSQL/SQLite (Prisma/Drizzle/`node:sqlite`) — интерфейс `read/write/update` уже изолирован.
2. **Сессии в памяти.** При рестарте сервера сессии сбрасываются; вынесите в Redis или подписывайте cookie с `exp`.
3. **Один администратор.** Нет ролей/приглашений/восстановления пароля — добавьте при необходимости.
4. **Изображения.** Сейчас исходные фото скопированы с azbut.by для демонстрации; подтвердите права и замените при релизе. Нужен ресайз/AVIF и `srcset` для всех карточек.
5. **Почта.** Формы пишут лид в JSON, но не отправляют email/Telegram-уведомление — подключите SMTP или бот.
6. **HTTPS/домен.** Задайте `SITE_ORIGIN=https://azbut.by`, включите `Secure` на cookie, 301 `www → без www`, 301 со старых URL Tilda на новые.
7. **Правовые документы.** Добавьте полноценную политику обработки персональных данных и cookie-баннер (в прототипе есть согласие в форме и `/terms`).
8. **Полевые метрики.** После запуска подключите Метрику/GA4 и проверьте CrUX / Search Console / Яндекс Вебмастер.
9. **Кэш.** Для HTML можно добавить ETag/`stale-while-revalidate`; для ассетов — хеши в именах файлов и `immutable`.
